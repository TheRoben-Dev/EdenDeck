# Eden integration reference

Everything EdenDeck knows about Eden lives here and, in code, in `eden_adapter`. Eden is
treated as an external, unmodified binary. We only touch it through CLI arguments, its INI
files, its data/mod directories, environment variables and a Vulkan layer.

## 2. Command-line flags

### Stable v0.2.1, Qt `eden` (`src/yuzu/main_window.cpp` ~L630-700)

Hand-rolled parser, single-dash only:

| Flag | Meaning |
|---|---|
| `-f` | fullscreen (sets the Fullscreen action) |
| `-g <path>` | game to boot |
| `-u <idx|name>` | user profile, 0-7 or username |
| `-input-profile <name>` | sets player 1's input profile name |
| `-qlaunch` | boot the firmware home menu applet |
| `-setup` | boot the firmware setup applet |
| `<path>` | any other argument is treated as the game path |

There is **no `-c`/`--config` on the Stable Qt frontend.**

### Nightly, Qt `eden` and `eden-cli` (shared parser `src/core/launch_params.cpp`)

Nightly moved parsing into `Core::ParseLaunchParams` with `getopt_long`, short string
`"dc:fhg:m:p:u:vinsx"`:

| Flag | Meaning | Status |
|---|---|---|
| `-f`, `--fullscreen` | fullscreen | safe |
| `-g`, `--game <path>` | game path | safe |
| `-u`, `--user <idx|name>` | user profile 0-7 | safe |
| `-c`, `--config <path>` | config file. Only `eden-cli` uses it (`SdlConfig config{lp.config_path}`); the Qt frontend parses and ignores it. | cli only |
| `-v`, `--version` / `-h`, `--help` | print and exit (via the logger) | safe |
| `-n`, `--null-render` | force Null renderer | safe |
| `-s`, `--singlecore` | disable multicore | safe |
| `-m`, `--multiplayer nick:pass@host:port` | join room | not used |
| `-p`, `--program <args>` | program args | not used |
| `-qlaunch`, `-hlaunch`, `-setup` | applets (non-option fallthrough) | not used |
| `-i`, `--input-profile` | **broken**: declared `no_argument` and short `i` has no `:`, then reads `optarg` (null). Do not pass. | avoid |
| `-d`, `--debug` | **broken** the same way (`atoi(optarg)` with no argument). | avoid |
| `-x`, `--filter` | reads `argv[optind]` manually. | avoid |

Note `-input-profile` (single dash) is the Stable spelling. On Nightly, `getopt_long` reads
it as the short cluster `-i -n -p ...`, which hits the broken `-i` path. **Never pass
`-input-profile` to Nightly.**

### Adapter rule

The only flags that mean the same thing on both channels are **`-f`, `-g <path>`, `-u <n>`**.
Launch as:

```
eden -f -g "/path/to/game.nsp"
```

Input profiles are selected by writing the per-game config (section 5), not by CLI.

**[install]** Unverified behaviour that matters for the frontend: whether the Qt window
closes when the guest exits or the user stops emulation (probably not: the Qt main window
stays up), and how `fullscreen_mode` (default `Exclusive` on Linux) behaves under
gamescope and Wayland. The frontend should own the process lifetime (terminate on "Exit
game" from our quick menu) until this is tested.

## 3. Directories

`src/common/fs/path_util.cpp` (`PathManagerImpl::Reinitialize`), names in
`src/common/fs/fs_paths.h`. Linux, non-portable:

| What | Path | Since |
|---|---|---|
| Data root (`EdenDir`) | `$XDG_DATA_HOME/eden` (default `~/.local/share/eden`) | both |
| Config (`ConfigDir`) | `$XDG_CONFIG_HOME/eden` (default `~/.config/eden`) | both |
| Cache (`CacheDir`) | `$XDG_CACHE_HOME/eden` (default `~/.cache/eden`) | both |
| Shader cache (`ShaderDir`) | Stable: `<data>/shader` · **Nightly: `<cache>/shader`** | moved |
| Keys | `<data>/keys` (`prod.keys`, `title.keys`, `dev.keys`) | both |
| NAND | `<data>/nand` (saves live under NAND) | both |
| SD card | `<data>/sdmc` | both |
| Mods (`LoadDir`) | `<data>/load/<TITLEID>/` | both |
| SD mods | `<data>/sdmc/atmosphere/contents/<TITLEID>/` (`filesystem.cpp` L730) | both |
| Dumps | `<data>/dump` | both |
| Screenshots, TAS, amiibo, log, icons, play_time, crash_dumps | `<data>/<name>` | both |
| Lossless Scaling DLL | `<data>/lossless/Lossless.dll` (+ `lsfg_spirv.cache`) | **Nightly only** |
| Post-process shaders / presets | `<data>/post_shaders`, `<data>/post_presets` | **Nightly only** |

**Portable mode:** if a directory named `user` exists in the **current working directory**
(not the binary's directory) on Linux, everything goes under `./user/` with `config/` and
`cache/` subfolders. The adapter must check the working directory it launches Eden from and
must not accidentally launch from a directory containing `user/`.

**Path overrides** in the global config, section `[Data%20Storage]`: `nand_directory`,
`sdmc_directory`, `load_directory`, `dump_directory`, `tas_directory`, `save_directory`
(`frontend_common/config.cpp` `ReadDataStorageValues`). The adapter must read these before
resolving any of the paths above.

**Legacy dirs** Eden may migrate from: `yuzu`, `suyu`, `sudachi`, `citron` under the same XDG
roots, and `Ryujinx` under `$XDG_CONFIG_HOME`.

### Firmware and keys

* Keys: copy the user's `prod.keys` and optional `title.keys` into `<data>/keys/`
  (`core/crypto/key_manager.cpp` L575-578). `prod.keys` is required.
* Firmware: Eden's own installer clears `<nand>/system/Contents/registered/` and copies the
  firmware `.nca` files into it (`qt_common/util/content.cpp` `InstallFirmware`). EdenDeck does
  the same from a user-selected folder or zip, after validation.
* EdenDeck never downloads, bundles or links to keys, firmware or games.

### Per-game key and firmware sets (design, untested)

Requested feature: the user imports several of their own `prod.keys`/`title.keys` (and
firmware) sets, then assigns a set per game.

What the source allows:

* The keys dir is always `<EdenDir>/keys` (`key_manager.cpp` L565). Unlike NAND/SD/load, it
  has **no config override**, CLI flag or dedicated env var.
* `EdenDir` itself is chosen per process: `./user/` in the **working directory** if it
  exists (portable mode), else `$XDG_DATA_HOME/eden`. Keys are loaded once per process.
* Firmware lives in `<nand>/system/Contents/registered/`. The same `nand/system` tree also
  holds system saves (user profiles etc.), so it must not be swapped wholesale.

Plan: a **per-launch portable root built from symlinks**. Nothing in the user's real Eden
dirs is modified, and launching Eden by hand keeps working normally.

```
$XDG_RUNTIME_DIR/edendeck/launch/<TITLEID>/        <- Eden's working directory
  user/                                            <- portable EdenDir
    keys/            -> ~/.local/share/edendeck/keysets/<set>/      (selected set)
    nand/
      system/
        Contents/registered -> .../keysets/<set>/firmware/  (only if the set has firmware)
        Contents/placehld   -> real nand/system/Contents/placehld
        save/        -> real nand/system/save    (profiles, system saves stay shared)
        (other entries)  -> real
      user/          -> real nand/user           (game saves stay shared)
      (other entries) -> real
    config/          -> ~/.config/eden           (same global + per-game configs)
    cache/           -> ~/.cache/eden
    load/, sdmc/, dump/, screenshots/, ... -> real dirs
```

Games without an assigned set launch normally, with no farm.

Rules: build the farm right before launch and remove it after Eden exits. Honour the
`[Data%20Storage]` overrides when resolving the "real" targets. Eden writes
`prod.keys_autogenerated` into the keys dir, so each set gets its own copy, which is
intended. Fallback if symlinked dirs turn out to break something: swap a single real
`keys` symlink before launch.

**[install]** Must verify: Eden follows symlinked directories in its VFS for reads and for
saves; portable mode is detected when the working directory is a symlink farm on tmpfs; the
per-game config still applies (it does, since `config/` points at the same dir).

## 4. Config files

All are INI files written by `frontend_common/config.cpp` via SimpleIni, QSettings-compatible.

| File | Purpose |
|---|---|
| `<config>/qt-config.ini` | Global config of the Qt frontend (`QtConfig(config_name = "qt-config")`) |
| `<config>/sdl2-config.ini` | Global config of `eden-cli` (separate file, or `-c <path>`) |
| `<config>/custom/<TITLEID>.ini` | Per-game overrides. `TITLEID` is `std::format("{:016X}")`, 16 uppercase hex digits. Homebrew without a title ID uses the file name. |
| `<config>/input/<name>.ini` | Named input profiles |
| `<config>/window_state.ini` | Qt window state, not touched |

### Key encoding

* Section = `TranslateCategory(category)`, e.g. `Renderer`, `Core`, `Cpu`, `System`,
  `Controls`, `UI`, `Data%20Storage` (spaces become `%20`, `/` becomes `\`).
* Each saved setting writes `key\default=<true|false>` and `key=<value>`. On read, if
  `key\default=true` the value is ignored and the built-in default is used.
* Per-game files: each switchable setting additionally has `key\use_global=<true|false>`.
  Only `use_global=false` keys are applied. Non-switchable settings are ignored in per-game files.
* **Enums are written as their integer index, not their name**
  (`settings_setting.h`, `ToString` uses `underlying_type`). Index tables are per-version, see below.
* Booleans `true`/`false`; strings with special characters are double-quoted (QSettings compat).
* Arrays use QSettings form: `name\1\field=...`, `name\size=N`.
* On every load Eden re-saves the file (`Config::Reload` calls `SaveValues`), so **Eden
  rewrites any file it reads**. Unknown keys are dropped on rewrite: **never store EdenDeck
  data inside Eden's INI files**, and only write while Eden is not running.

### Settings the UI exposes (verified on both channels)

| UI option | Section | Key | Type / values (index = INI value) |
|---|---|---|---|
| Renderer | Renderer | `backend` | `RendererBackend`: 0 OpenGL_GLSL, 1 Vulkan, 2 Null, 3 OpenGL_GLASM, 4 OpenGL_SPIRV |
| Resolution scale | Renderer | `resolution_setup` | 0 ¼x, 1 ½x, 2 ¾x, **3 1x**, 4 1.25x, 5 1.5x, 6 2x, 7 3x, 8 4x, 9 5x, 10 6x, 11 7x, 12 8x |
| Window scaling filter | Renderer | `scaling_filter` | 0 Nearest, 1 Bilinear, 2 Bicubic, 3 Gaussian, 4 Lanczos, 5 ScaleForce, **6 Fsr**, 7 Area, 8 ZeroTangent, 9 BSpline, 10 Mitchell, 11 Spline1, 12 Mmpx; Nightly adds 13 Sgsr, 14 SgsrEdge |
| FSR sharpening | Renderer | `fsr_sharpening_slider` | int 0-200, default 25 |
| Anti-aliasing | Renderer | `anti_aliasing` | 0 None, 1 Fxaa, 2 Smaa |
| VSync | Renderer | `use_vsync` | `VSyncMode`: 0 Immediate, 1 Mailbox, **2 Fifo**, 3 FifoRelaxed |
| Fullscreen mode | Renderer | `fullscreen_mode` | 0 Borderless, 1 Exclusive (Linux default) |
| Aspect ratio | Renderer | `aspect_ratio` | `AspectRatio` enum |
| Disk shader cache | Renderer | `use_disk_shader_cache` | bool |
| Async shaders | Renderer | `use_asynchronous_shaders` | bool |

All of the above are per-game switchable on both channels.

### Cross-version hazards found (the reason the adapter is versioned)

* **`gpu_accuracy` enum changed.** Stable `2` (High) is out of range on Nightly; Nightly `1`
  (High) means Medium on Stable. The adapter must translate by name, never copy integers.
* Other enum table changes Stable → Nightly: `AnisotropyMode` lost X32/X64/None,
  `CpuClock` renamed values, `GpuOverclock` replaced by `GpuClock`, `AppletMode` gained values,
  `ScalingFilter` gained Sgsr/SgsrEdge (index 13 was `MaxEnum` on Stable).
* **Settings moved sections:** `fast_cpu_time` `[Cpu]` → `[System]`, `fast_gpu_time`
  `[Renderer]` → `[System]`.
* Nightly-only keys include: `frame_gen*`, `post_shader_*`, `cheat_overlay`,
  `enable_cheats_by_default`, `builtin_pad_*` (Steam handle related), `console_*` applet
  options, `gpu_fence_behavior`, `disable_wgi_xinput`. Removed on Nightly: `rescale_hack`,
  `gpu_logging_enabled`, `eden_token`, `dump_shaders` (renamed `dump_guest_shaders`).
* Full list: diff the two JSON snapshots.

Adapter policy: detect the Eden version, load the matching schema (nearest older snapshot
for unknown builds), write only keys present in that schema, translate enums by name, and
leave unknown keys in existing files alone. If the installed version is newer than every
snapshot, treat writes to keys missing from the latest snapshot as unsupported and show it.

## 5. Per-game config

`<config>/custom/<TITLEID>.ini`, loaded by the Qt frontend at boot
(`main_window.cpp`, `QtConfig per_game_config(config_file_name, PerGameConfig)`), so passing
`-g` is enough for it to apply. Format per key:

```ini
[Renderer]
resolution_setup\use_global=false
resolution_setup\default=false
resolution_setup=6
use_vsync\use_global=true
```

Per-game input: `[Controls]` with `player_<n>_profile_name=<profile>` (see
`Config::ReadPlayerValue`); with a per-game file, players fall back to the global config unless
a profile name is set. Details for phase 3.

## 6. Mods, cheats and disabled add-ons

`core/file_sys/patch_manager.cpp`, same behaviour on both channels.

### Layout

```
<data>/load/<TITLEID>/<ModName>/
    exefs/      *.ips (named <build-id>.ips) and *.pchtxt  -> NSO patches
                other files replace ExeFS files
    romfs/      LayeredFS replacement files
    romfs_ext/  LayeredFS extension layer
    cheats/     <BUILDID>.txt  (first 16 hex chars of the build ID, upper or lower case)
<data>/load/<TITLEID>/cheat_*.txt   loose cheat files (loaded if name starts with cheat_)
<data>/sdmc/atmosphere/contents/<TITLEID>/   Atmosphère-style SD mods, add-on name "SDMC"
```

* Subfolder names (`exefs`, `romfs`, `romfs_ext`, `cheats`) are matched case-insensitively.
* Title IDs are 16 uppercase hex digits. Mods are not loaded for title ID 0 or for update
  title IDs (`(id & 0xFFF) == 0x800`). DLC/variant titles also see mods of their parent title.
* **Load order:** mod folders are sorted by name (`std::sort` on `GetName()`), and the
  **first** layer wins in `LayeredVfsDirectory` (`vfs_layered.cpp`). So `A_mod` overrides
  `Z_mod` for the same romfs path. EdenDeck implements load order by managing a name prefix
  (e.g. `010_`), and warns when two enabled mods ship the same romfs path.

### Disabled add-ons

Stored in the **global** config only (`ReadDisabledAddOnValues` runs only for the global
config), section `[DisabledAddOns]`, QSettings array form:

```ini
[DisabledAddOns]
size=1
1\title_id=72057594037927936
1\disabled\size=2
1\disabled\1\d=MyMod
1\disabled\2\d=Update
```

* `title_id` is written as a **decimal** integer.
* Entries are add-on names matched exactly:
  * a mod folder name under `load/<TITLEID>/`
  * a loose cheat file name (`cheat_xyz.txt`)
  * `SDMC` (all SD mods for the title)
  * `Update`, `Update@<version>`, `Update (NAND)`, `Update (SDMC)`
  * DLC entries (names from the add-ons list in the Qt UI, to confirm **[install]**)
* Enable/disable therefore needs no file moves. Write only while Eden is not running,
  because Eden rewrites `qt-config.ini` on exit.

## 7. Eden's own release feeds (for the Eden manager)

From `CMakeModules/GenerateSCMRev.cmake` and `src/common/net/net.cpp`:

| Channel | Feed |
|---|---|
| Stable | `https://stable.eden-emu.dev/latest/release.json` and Forgejo API `https://git.eden-emu.dev/api/v1/repos/eden-emu/eden/releases` |
| Nightly | `https://nightly.eden-emu.dev/latest/release.json` (builds from `eden-ci/nightly`) |

The release JSON has GitHub-style `tag_name`, `assets[]` with `name`, `size`, `digest`,
`browser_download_url`. Eden's built-in updater has no Linux AppImage branch, so EdenDeck
must handle Linux updates. Linux asset file names, and whether `digest` is populated
(`sha256:...`), are **[install]**: they could not be fetched from here. The manager will
select assets by suffix (`.AppImage`) and architecture, and verify `digest` when present.

## 8. Built-in features that change our plans

Found during the spike; relevant to phases 5 and the lsfg-vk request.

* **Spatial FSR 1 already exists on both channels**: `scaling_filter=6` (Fsr, EASU + RCAS)
  with `fsr_sharpening_slider`. It runs inside Eden before the final blit, on the
  game-resolution image and before the window scale. A spatial FSR pass in our layer would
  see the same frame later, after Eden's own scaling, and can't do better. "FSR spatial" in
  our UI should therefore just drive Eden's setting.
* **Nightly has built-in frame generation using Lossless Scaling's shaders** (lsfg-vk code,
  `video_core/frame_gen/lossless_dll.*`, `renderer_vulkan/present/frame_gen*.cpp`). It needs the
  user's own `Lossless.dll` at `<data>/lossless/Lossless.dll`. Settings (all per-game, `[Renderer]`):

  | Key | Type | Default | EdenDeck value |
  |---|---|---|---|
  | `frame_gen` | bool | false | on only for titles below 60 fps |
  | `frame_gen_multiplier` | u32 2-4 | 2 | **always 2** |
  | `frame_gen_target_rate` | u32 0-240 (0 = off) | 0 | **60** |
  | `frame_gen_flow_scale_auto` | bool | true | true |
  | `frame_gen_flow_scale` | u32 25-100 | 75 | exposed as Performance/Quality |
  | `frame_gen_queue_target` | u32 0-2 | 0 | 0 (lowest latency) |

  It sits inside Eden's presenter, so it knows real frames from repeats, and it knows the guest
  render extent. That's better input than a present-time layer gets.
* **Lossless.dll on SteamOS:** Lossless Scaling installed through Steam (Proton) lands in
  `<steam library>/steamapps/common/Lossless Scaling/Lossless.dll`. The library list is in
  `~/.local/share/Steam/steamapps/libraryfolders.vdf` (also `~/.steam/steam/...`, Flatpak Steam
  `~/.var/app/com.valvesoftware.Steam/.local/share/Steam/...`). EdenDeck copies the user's own
  file into Eden's `lossless/` dir; it never ships or downloads it. Expected Steam path is
  **[install]**.
* **External lsfg-vk** (the standalone Vulkan layer) is the fallback for Stable Eden. It is
  configured through its own config file and env vars. Its current config format must be
  checked against lsfg-vk's own repo before phase 5 **[not yet researched]**.
* **Frame-gen cap (product rule):** the goal is 60 fps. Only 2x, only for titles running
  below 60, output never above 60. Native 60 fps titles get no frame gen. Applies to Eden's
  built-in frame gen, lsfg-vk and our own layer. Only one frame-gen path can be active at a
  time.

## 9. Environment variables we set on the Eden process

| Var | Purpose |
|---|---|
| `VK_ADD_LAYER_PATH=<dir with VkLayer_EDENDECK_fsr.json>` | make our explicit layer discoverable |
| `VK_INSTANCE_LAYERS=VK_LAYER_EDENDECK_fsr` | enable it for this process only |
| `EDENDECK_LAYER_STATS=$XDG_RUNTIME_DIR/edendeck/stats.json` | layer → frontend stats |
| `DISABLE_EDENDECK_LAYER=1` | kill switch (layer becomes pass-through) |

`VK_ADD_LAYER_PATH` needs Vulkan loader 1.3.234 or newer. SteamOS 3.6+ and current Bazzite ship
newer loaders. The Eden AppImage may bundle its own `libvulkan.so.1` **[install]**, so check
which loader the AppImage uses.

## 10. Verification checklist (needs a real install)

1. Cross-check both commit hashes against git.eden-emu.dev.
2. Fetch both `release.json` feeds: record Linux asset names and whether `digest` is set.
3. Extract the Stable and Nightly AppImages (`--appimage-extract`): does `eden-cli` exist? Is
   `libvulkan.so.1` bundled? What does `AppRun` set (e.g. `QT_QPA_PLATFORM`)?
4. Launch `eden -f -g <game>` on both channels. Confirm fullscreen, the per-game config
   applies, and what happens on guest exit.
5. Write a `custom/<TITLEID>.ini` override (e.g. `resolution_setup=6`) and confirm it applies,
   and that Eden rewrites but keeps it.
6. Toggle a mod in `[DisabledAddOns]` with Eden closed. Confirm the Qt add-ons tab shows it
   disabled, then check the DLC naming.
7. Nightly: copy a user-owned `Lossless.dll` into `lossless/`, set `frame_gen=true`,
   multiplier 2, target 60 in a per-game file, and confirm it works under gamescope.
8. Run the layer test procedure in `layer/README.md` on X11, Wayland and gamescope.
